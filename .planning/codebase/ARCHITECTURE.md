# Architecture

**Analysis Date:** 2026-11-15

## System Overview

```text
┌─────────────────────────────────────────────────────────────┐
│                    Card content (Markdown)                   │
│   `src/content/cards/*.md`   (generated by `npm run cards`)  │
│   images: `src/assets/cards/`                                │
└──────────────┬───────────────────────────────┬──────────────┘
               │ getCollection('cards')        │ milestones (JS)
               ▼                               ▼
┌─────────────────────────────────────────────────────────────┐
│           Pure logic (no I/O, no DOM)                        │
│   `src/lib/cards.js`  `src/lib/countdown.js`  `src/lib/meta.js` │
│   `src/data/site.js`  `src/data/milestones.js`               │
└──────────────┬───────────────────────────────┬──────────────┘
               │ timelineEntries()             │ daysBefore()
               ▼                               ▼
┌─────────────────────────────────────────────────────────────┐
│           Astro pages and components (render only)           │
│   `src/pages/*.astro` → `src/components/*.astro`             │
│   layout: `src/layouts/Base.astro`                           │
└──────────────┬──────────────────────────────────────────────┘
               │ astro build (static HTML + hashed /_astro/)
               ▼
┌─────────────────────────────────────────────────────────────┐
│  `dist/` → Docker image (`Dockerfile`, nginx:alpine)         │
│  `deploy/nginx.conf` serves it on :80 behind Cloudflare Tunnel │
└─────────────────────────────────────────────────────────────┘
```

Client-side behaviour is small. Three plain scripts run in the browser:
`src/scripts/countdown.js`, `src/scripts/media.js` and `src/scripts/share.js`.

## Pattern Overview

**Overall:** Static site (Astro 7, `output` left at the default static mode). Content lives in a typed content
collection. Pure functions decide order, timeline and countdown. Templates only render.

**Key Characteristics:**
- No server runtime. Every route is prerendered at build time. nginx serves the files.
- One source of content: one Markdown file per card. Each file is written by `scripts/sync-cards.js`
  from `research/candidates.json`. The JSON is the one place to edit.
- Logic lives in `src/lib/` as pure, JSDoc-typed functions. `src/__tests__/` covers them with Vitest.
- Type checking is done with JSDoc, not TypeScript: `jsconfig.json` sets `checkJs` and `strict`.
- Browser scripts are shipped as separate files. `vite.build.assetsInlineLimit` is 0 in `astro.config.mjs`,
  so no inline `<script>` is needed. This keeps the CSP free of `'unsafe-inline'` (`deploy/nginx.conf`).
- Two external scripts: Umami (`umami.lav.ren`) loads on every host and counts on the apex only (`data-domains`
  in `src/layouts/Base.astro`). AdSense (Google) loads on the apex only. `AGENTS.md` and `deploy/README.md` record both.

## Layers

**Content (data source):**
- Purpose: Hold each card as frontmatter plus an image reference.
- Location: `src/content/cards/*.md`, `src/assets/cards/`, schema in `src/content.config.js`.
- Contains: Frontmatter with `title`, `blurb`, `kind`, `date`, `source`, `image`, `imageAlt`, `nsfw`, `status`.
- Depends on: Nothing at runtime. Written by `scripts/sync-cards.js` and `scripts/lib/candidate.js`.
- Used by: `getCollection('cards')` in `src/components/Timeline.astro` and `src/pages/[id].astro`.

**Pure library:**
- Purpose: Order cards and milestones, build the timeline, compute the countdown, build page titles.
- Location: `src/lib/cards.js`, `src/lib/countdown.js`, `src/lib/meta.js`.
- Contains: `timelineEntries`, `ogImageOf`, `splitTitle`, `daysBefore`, `remaining`, `pageTitle`.
- Depends on: Types from `astro:content` (type imports only).
- Used by: Pages, components and `src/scripts/countdown.js`.

**Configuration and data constants:**
- Purpose: Hold the launch date, site URLs, analytics and ad IDs, and the milestone list.
- Location: `src/data/site.js` (`LAUNCH`, `SITE_URL`, `ADSENSE_CLIENT`, `UMAMI_WEBSITE_ID`),
  `src/data/milestones.js`.
- Depends on: Nothing.
- Used by: Layout, timeline, countdown script, card page.

**Presentation:**
- Purpose: Render HTML.
- Location: `src/layouts/Base.astro` (document shell, head tags, third-party loaders),
  `src/components/` (`Header.astro`, `Footer.astro`, `Countdown.astro`, `Timeline.astro`,
  `TimelineItem.astro`, `Card.astro`), `src/styles/global.css`.
- Depends on: Pure library and data constants.
- Used by: Pages.

**Browser behaviour:**
- Purpose: Small progressive enhancements. The page works without them.
- Location: `src/scripts/countdown.js` (minute-step countdown; flips the title at launch),
  `src/scripts/media.js` (Escape hides a row's hover image, WCAG 1.4.13), `src/scripts/share.js`
  (copy-link button on the card page).
- Depends on: `src/lib/countdown.js`, `src/data/site.js`.
- Used by: Imported by `Timeline.astro` and `[id].astro` through `<script>` tags.

## Data Flow

### Primary Request Path (the home page)

1. A request for `/` reaches nginx, which serves the prerendered `dist/index.html`
   (`deploy/nginx.conf`, `location /`).
2. At build time, `src/pages/index.astro` renders `<Timeline order="newest" />`.
3. `Timeline.astro` calls `getCollection('cards')` and passes the result with `milestones` to
   `timelineEntries(cards, milestones, order)` in `src/lib/cards.js`.
4. `timelineEntries` keeps only `status === 'launch'` cards, merges milestones, sorts by date, then
   milestone-before-card, then title. For `newest` it reverses the list.
5. `Timeline.astro` groups entries by UTC year with `Map.groupBy`. Each year becomes a `<section>` with an `<ol>`.
6. Each entry renders through `src/components/TimelineItem.astro`. The countdown in `Header.astro` is filled
   by `src/scripts/countdown.js` in the browser.

### Card Page Path (`/<id>/`)

1. `src/pages/[id].astro` `getStaticPaths` builds the same timeline, newest first, and takes only cards.
2. Each card gets `newer` and `older` neighbours from that order. These feed the pager.
3. `Card.astro` renders the card at `headingLevel={1}`, `eager`, `large`. It shows the full image, the facts link and the
   image credit when set.
4. The `Base.astro` layout sets the title with `pageTitle` (`src/lib/meta.js`) and the Open Graph image with
   `ogImageOf` (NSFW cards get the site image instead).

### Content Pipeline (build-time, not runtime)

1. Edit `research/candidates.json` (the single source of truth).
2. Run `npm run cards` (`scripts/sync-cards.js`). It validates with `checkCandidates`, downloads missing
   images, writes `src/content/cards/<id>.md` with `cardMarkdown`, removes non-launch cards, moves their images to
   `research/images/`, and rewrites `research/candidates.md`.
3. `src/__tests__/content.test.js` fails if a card differs from what the sync would write.
4. CI (`.github/workflows/ci.yml`) runs lint, test, build and html-validate. `build.yml` builds the image.

### Deploy Path

1. A push to `develop` or `main` runs `.github/workflows/build.yml`.
2. The workflow builds `dist/`, builds the multi-arch image `ghcr.io/elfensky/beforegta6:sha-<commit>`, and runs
   `scripts/pin-image.sh`.
3. The pin script writes that tag into `deploy/staging/compose.yaml` or `deploy/production/compose.yaml` and commits it.
4. Arcane Git Sync applies the compose file to the Pi swarm (staging) or the Hetzner swarm (production).
   Traffic reaches two `web` replicas through a Cloudflare Tunnel (`cloudflared`) at `http://web:80`.

**State Management:**
- None on the server. Pages are static. The only client state is the Escape-dismissed class on `.entry` rows,
  set in `src/scripts/media.js`.

## Key Abstractions

**`TimelineEntry` (`src/lib/cards.js`):**
- Purpose: One row on the timeline. Either a card or a GTA milestone.
- Shape: `{ kind: 'card', date, year, card }` or `{ kind: 'milestone', date, year, milestone }`.
- Pattern: Discriminated union. Components branch on `entry.kind` (see `TimelineItem.astro`).

**Card (content entry):**
- Purpose: One item on the site.
- Examples: `src/content/cards/gdpr.md`, `src/content/cards/trump-mugshot.md`.
- Pattern: Astro content collection with a Zod schema in `src/content.config.js`. Images are imported with
  `image()` so Astro optimizes them.

**Candidate (research record):**
- Purpose: One find before it becomes a card.
- Examples: `research/candidates.json`, typed in `scripts/lib/candidate.js`.
- Pattern: Pure functions (`toCard`, `checkCandidates`, `cardMarkdown`, `reviewTable`) with no I/O. The sync
  script does the I/O.

**Milestone:**
- Purpose: A dated GTA event on the timeline (release, delays, trailers).
- Examples: `src/data/milestones.js`.
- Pattern: Plain array of objects, typed by the `Milestone` typedef in `src/lib/cards.js`.

## Entry Points

**Home page:**
- Location: `src/pages/index.astro`
- Triggers: `GET /`
- Responsibilities: Renders the newest-first timeline.

**Oldest-first timeline:**
- Location: `src/pages/oldest.astro`
- Triggers: `GET /oldest/`. Excluded from the sitemap (`astro.config.mjs`). Canonical stays on `/`.
- Responsibilities: Renders the oldest-first timeline.

**Card page:**
- Location: `src/pages/[id].astro`
- Triggers: `GET /<card-id>/`, one page per launch card.
- Responsibilities: Full card, share button, previous and next cards.

**Other pages:** `src/pages/privacy.astro`, `src/pages/404.astro` (nginx serves it through `error_page 404`).

**Legacy redirect:** `deploy/nginx.conf` sends `/timeline/` to `/` with a 301.

**Build entry:** `astro build` (`npm run build`), used by CI and by `Dockerfile` indirectly through `dist/`.

**Content generator:** `scripts/sync-cards.js` (`npm run cards`).

**Container entry:** `Dockerfile` copies `deploy/nginx.conf` and `dist/` into `nginx:1.30-alpine`.

## Architectural Constraints

- **Threading:** Not applicable. Build runs in Node. The browser runs single-threaded scripts only.
- **Global state:** `src/data/site.js` exports constants used everywhere. `src/data/milestones.js` is one shared array.
  Nothing mutates them. `timelineEntries` sorts the array it builds, not the inputs.
- **Circular imports:** None observed. `src/lib/` does not import from `components/` or `pages/`.
- **Pure logic rule:** `AGENTS.md` requires that order, timeline and countdown logic stay in `src/lib/`. `.astro`
  files only render.
- **Asset rule:** Every card image sits in `src/assets/cards/`. An image of a card that is not live stays in
  `research/images/`, because Astro ships every imported image (`deploy/README.md` § Removing or holding a card).
- **Image tag rule:** The `image:` line in the compose files is written by CI only.
- **Script delivery:** Inline `<script>` tags are not allowed, except the two `is:inline` loaders in `Base.astro`,
  which come from documented exceptions. The nginx CSP has no `script-src`.

## Anti-Patterns

### Editing a card file by hand

**What happens:** A card's Markdown is changed directly in `src/content/cards/`.
**Why it's wrong:** `npm run cards` overwrites it on the next run. `src/__tests__/content.test.js` fails.
**Do this instead:** Change the entry in `research/candidates.json`, then run `npm run cards`
(`scripts/sync-cards.js`).

### Importing an image of a card that is not live

**What happens:** An image for a `hold` or `drop` card stays in `src/assets/cards/`.
**Why it's wrong:** Astro ships every imported image, so a held card's picture stays public.
**Do this instead:** Let `scripts/sync-cards.js` move it to `research/images/`.

### Rendering logic inside `.astro` files

**What happens:** Sorting or filtering code is written inside a component's frontmatter.
**Why it's wrong:** It cannot be unit-tested under Vitest, and it breaks the rule in `AGENTS.md`.
**Do this instead:** Add a pure function to `src/lib/cards.js` (see `timelineEntries`) and test it in `src/__tests__/`.

### Inline scripts

**What happens:** `<script>` content is inlined into the HTML.
**Why it's wrong:** It needs `'unsafe-inline'` in the CSP, which `deploy/nginx.conf` does not allow.
**Do this instead:** Put the code in `src/scripts/*.js` and import it from a `<script>` tag, as `Timeline.astro` does.

## Error Handling

**Strategy:** Fail at build time. Validation happens before any write.

**Patterns:**
- `scripts/sync-cards.js` runs `checkCandidates` first. Any problem stops the run with nothing written.
- The Zod schema in `src/content.config.js` rejects a bad card at build time.
- `src/lib/meta.js` truncates titles to 70 characters so the page title passes html-validate.
- nginx returns `404.html` for unknown paths and uses `stale-if-error` at the edge.

## Cross-Cutting Concerns

**Logging:** `console.log` and `console.error` in `scripts/sync-cards.js` only. The site has no runtime logging.
**Validation:** Build-time through `src/content.config.js` (Zod) and `scripts/lib/candidate.js`.
**Authentication:** Not applicable. The site is public. The admin path is `Arcane` and `Cloudflare Zero Trust`, outside the repo.
**Analytics:** Umami on the apex only (`UMAMI_WEBSITE_ID` in `src/data/site.js`).
**Caching:** HTML `max-age=0` for browsers and 5 minutes at Cloudflare (`deploy/nginx.conf`). `/_astro/` is immutable for a year.
**Security headers:** Set in `deploy/nginx.conf`. Frame, MIME and referrer headers, HSTS, a narrow CSP.
